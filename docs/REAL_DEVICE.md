# ডেমো থেকে আসল মেশিনে — সৎ গাইড

> প্রশ্নটা ঠিক ছিল: **ডেমো ডেটা মানে ডেমোই।** এখানে পরিষ্কার করে লিখছি কী সত্যিই
> প্রমাণিত, কী এখনো অনুমান, আর আসল মেশিনের ডেটা কীভাবে নেবেন।

---

## ১. আসল মেশিন আর ডেমোর পার্থক্য কোথায়

| বিষয় | ডেমো (HTTP form) | আসল অ্যানালাইজার |
|---|---|---|
| হ্যান্ডশেক | নেই | **ENQ → ACK** আগে, তারপর ডেটা |
| ফ্রেম | পুরো মেসেজ একসাথে | `STX` ⟨ফ্রেম নম্বর⟩ ডেটা `ETX` ⟨চেকসাম⟩ — ছোট ছোট ব্লক |
| চেকসাম | নেই | প্রতি ব্লকে; ভুল হলে **NAK**, মেশিন আবার পাঠায় |
| শেষ | একটাই রেসপন্স | `EOT` দিয়ে শেষ, তারপর ACK |
| টাইমিং | মিলিসেকেন্ড | সিরিয়ালে ধীর, অপারেটর-নির্ভর, রিট্রাই |
| কেবল | TCP | প্রায়ই **RS-232 (9600 7E1)** |
| ব্যর্থতা | কেউ দেখে না | কেবল খুলে গেলে মেশিন আটকে যায় |

এই সবগুলো **এখন কোডে আছে** — `core/e1381.py` (ফ্রেমিং + চেকসাম) এবং
`listeners/tcp_listener.py` (হ্যান্ডশেক)। ৩৬টি টেস্টের ৮টি শুধু এই লেয়ারটাই
যাচাই করে।

## ২. আসল মেশিনের অনুভূতি — ৩ ধাপে

### ধাপ ১ · device_sim (সিমুলেটর, কিন্তু ওয়্যার-লেভেলে)

এটা HTTP ফর্ম নয় — এটা সত্যিকারের E1381 ট্রান্সমিশন করে:

```bash
python main.py --dry-run                       # টার্মিনাল ১
python tools/device_sim.py -s astm_cbc_normal -p 6661 --trace   # টার্মিনাল ২
```

আউটপুট (কমপক্ষে এই রকম):

```
→ analyzer: <ENQ>
← middleware: <ACK>
→ analyzer: <STX>1H|\^&|||Sysmex^XN-1000^A1234|…<ETX>?2
← middleware: <ACK>
…
→ analyzer: <EOT>
frames sent: 8 · acked: 8 · retries: 0 · messages accepted: 1
RESULT: the middleware behaved like a real LIS endpoint ✅
```

আর কেবল-এর সমস্যাগুলোও এখানেই বানানো যায়:

```bash
# প্রতি ১০টি ফ্রেমে ৪টির চেকসাম নষ্ট → NAK → রিট্রাই
python tools/device_sim.py -s astm_cbc_normal --fault checksum --fault-rate 0.4

# সিরিয়াল কেবলের নয়েজ (STX-এর আগে আজেবাজে বাইট)
python tools/device_sim.py -s astm_cbc_normal --fault noise --fault-rate 0.4

# মেশিন নিজেই একটা ব্লক হারিয়েছে
python tools/device_sim.py -s astm_cbc_normal --fault drop --fault-rate 0.25

# HL7/MLLP
python tools/device_sim.py -s hl7_critical -p 6662 --trace

# মিডলওয়্যার বন্ধ থাকলে ল্যাব কী দেখে
python tools/device_sim.py -s astm_cbc_normal -p 7000
```

শেষ লাইনটা স্ক্রিপ্টেও ব্যবহার করা যায় — সফল হলে exit code 0, নাহলে 1।

### ধাপ ২ · sniff_com (আসল মেশিনের আসল বাইট)

সিমুলেটর যতই ভালো হোক, **আপনার** Sysmex-এর ফারম্যাট সে জানে না। একবার আসল
ডেটা ধরা পড়লে সেটাই চিরকালের রেফারেন্স।

**ক) সিরিয়াল ট্যাপ (যদি মেশিন RS-232-এ চলে)**

```bash
python tools/sniff_com.py --port COM4 --baud 9600 --parity EVEN \
    --tap 127.0.0.1:6661 --out logs/capture.jsonl
```

মেশিনের কেবল একটা COM পোর্টে (com0com / হার্ডওয়্যার ট্যাপ) নিন — `sniff_com`
বাইট ধরে রাখে, মিডলওয়্যারকেও পাঠায়, আর ACK ফেরত দেয়। মেশিন কিছু জানে না।

**খ) TCP ট্যাপ (যদি মেশিন LAN-এ চলে)**

```bash
python tools/sniff_com.py --listen 0.0.0.0:6663 --tap 127.0.0.1:6661
```
মেশিনের Host সেটিং-এ IP/পোর্ট বদলে `6663` দিন, বাকি সব একই।

**গ) শুধু দেখতে চাইলে** — কোনোটাই না করে লগ চালু রেখে `lis_raw_messages`
টেবিল দেখুন; ওখানে প্রতিটা মেসেজ অক্ষত আছে।

### ধাপ ৩ · replay (আসল ডেটা বারবার টেস্ট)

```bash
python tools/replay_capture.py logs/capture.jsonl --list        # কয়টা সেশন
python tools/replay_capture.py logs/capture.jsonl --dry-run     # কী আছে দেখুন
python tools/replay_capture.py logs/capture.jsonl --port 6661 --timing
```

এরপর যতবার parser বদলাবেন, আসল মেশিনের রেকর্ড করা সেশন দিয়েই টেস্ট হবে।
এখানেই "ডেমো ডেটা" সমস্যাটা শেষ।

## ৩. Virtual Serial Port (com0com) দিয়ে পুরো সিস্টেম টেস্ট

আসল কেবল না থাকলেও সিরিয়াল পথটা টেস্ট করা যায়:

1. **com0com** ইনস্টল করুন → `COM3 ↔ COM4` পেয়ার বানান।
2. `config.yaml`-এ `connection_type: SERIAL`, `serial_port: COM3`।
3. `python main.py --dry-run` — এখন COM3 খোলা থাকবে।
4. অন্য দিক (COM4) থেকে ডেটা পাঠান: `python tools/device_sim.py` সিরিয়াল মোড
   চাইলে `mock_analyzer.py`-এর `--serial COM4` ব্যবহার করুন, বা যেকোনো টার্মিনাল
   (`mode COM4:9600,N,8,1` তারপর টাইপ করুন)।

এতে `serial_listener.py` + pyserial + E1381 রিসিভ — তিনটাই আসলভাবে চলে।

## ৪. Mirth Connect প্রসঙ্গে (যাচাই করা তথ্য)

* Mirth Connect (এখন NextGen Connect) **HL7 v2.x নেটিভভাবে বোঝে**, কিন্তু
  **ASTM E1394/E1381 নেটিভভাবে সাপোর্ট করে না** — ASTM ডেটা টাইপ ও E1381
  ট্রান্সমিশন-মোড আলাদা এক্সটেনশন, আর সেটি কমার্শিয়াল (সাপোর্ট কাস্টমারদের জন্য)।
* তাই ASTM-ভাষী মেশিনের ক্ষেত্রে Mirth দিয়ে সরাসরি "প্লাগ অ্যান্ড প্লে" হয় না;
  সাধারণত Basic TCP Listener-এ raw/delimited ডেটা নিয়ে নিজে চেকসাম/হ্যান্ডশেক
  সামলাতে হয় — অনেকটা এই প্রজেক্টে যা করা হয়েছে তার মতোই, শুধু Java-তে।
* HL7-ভাষী মেশিন (যেমন Mindray) হলে Mirth সহজ পথ, কারণ সেখানে MLLP + HL7
  পার্সিং বিল্ট-ইন।

সারমর্ম: **HL7 → Mirth সহজ; ASTM → দুটো রাস্তাতেই নিজের কাজ করতে হয়।**
এই প্রজেক্ট দুই ফরম্যাটই এক জায়গায় সামলায়, তাই মেশিন বদলালে আলাদা টুল শিখতে হয় না।

## ৫. যা এখনো প্রমাণিত নয় (সৎ তালিকা)

| বিষয় | অবস্থা |
|---|---|
| ASTM/HL7 পার্সিং, ভ্যালিডেশন, ডুপ্লিকেট, ACK | ✅ ৩৬টি টেস্ট + device_sim দিয়ে যাচাই |
| E1381 ফ্রেমিং, চেকসাম, NAK-রিট্রাই, নয়েজ রিসাইকেল | ✅ টেস্ট + সিমুলেটরে যাচাই |
| Oracle ইনসার্ট | ⚠️ কোড তৈরি, কিন্তু এই পরিবেশে Oracle নেই — আপনার DB-তে `--dry-run` বাদ দিয়ে একবার চালিয়ে দেখুন |
| আপনার নির্দিষ্ট মেশিনের ফিল্ড ম্যাপিং | ⚠️ নমুনা Sysmex/Mindray/Roche ফরম্যাট ধরে লেখা — আসল ডেটায় মিলিয়ে নিতে হবে |
| pyserial + আসল COM পোর্ট | ⚠️ কোড আছে, এই পরিবেশে COM পোর্ট নেই |
| মেশিনের Host সেটিং-এর নামগুলো | ⚠️ ব্র্যান্ডভেদে আলাদা ("Host Communication", "LIS Connection", "ASTM Online") |
